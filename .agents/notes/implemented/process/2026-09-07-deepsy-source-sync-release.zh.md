# Agent Note: 从同步后的源码发布桌面更新

Status: implemented

[English](2026-09-07-deepsy-source-sync-release.md) | 中文

## Problem

上游 npm 版本变新并不会更新桌面安装包内嵌的源码。只修改版本号的发布可能宣称升级，实际行为却没有变化。

## Decision

[GitHub 工作流](../../../../.github/workflows/deepsy-release.yml) 每六小时检查上游 Git 祖先关系。它将新源码合入 fork，只解决独立的版本字段冲突，安装依赖，并在打包和推送前运行桌面集成检查。普通推送会拒绝并发的 master 变更。已发布的标签与产物不被替换；上传完成前保持草稿。手动触发可以发布当前 master 版本，或只报告更新而不发布。

桌面版本跟随更新的上游版本。源码变化但上游版本未提升时，会递增 fork 修订号，保持更新检测的单调性。[Ad-hoc 签名](2026-08-18-adhoc-sign-macos-release-artifacts.zh.md) 仍由独立决策负责，保持不变。

原生依赖在隔离部署目录中为声明的 Electron 版本强制重建。系统 Node 的重建可能替换二进制文件却不删除 Electron ABI 标记，因此仅信任该标记可能打包不兼容的 addon。

## Alternatives considered

**只跟随 npm dist-tag 修改版本。** 拒绝，因为它只更改标签，没有引入上游实现。

**使用 Codex 调度器。** 拒绝，因为仓库工作流无需桌面会话即可运行，并且已经拥有打包凭证与日志。

**自动解决所有合并冲突。** 拒绝，因为上游接口变化时，桌面特有行为需要人工审查。此类冲突会停止发布，保留最后一个已发布版本。

## Consequences

桌面部署 manifest 显式提供必需的 workspace peer，因为生产部署不会自动安装它们。暂存步骤复用现有运行时依赖闭包检查；发布打包后还会在 Electron 下使用临时用户数据启动包内后端，再允许公开发布。仅源码侧浏览器检查无法发现生产依赖遗漏。翻译配对排除桌面构建产物，但仍检查桌面源码 README。

常规兼容变更可无需操作员介入而发布。冲突、检查失败和并发更新需要维护者处理；定时运行不保证每次都有新版本。针对版本与冲突的测试以及组装后的桌面启动检查保护从源码到安装包的流程。
